# V6 reconstruction

V6 adds sign ownership, typed CVE/SQLCODE full spans, overlap filtering, raw
literal fields, and diagnostic occurrence IDs. The full lexical candidate is
selected before a contained candidate, so `-204` owns `-204` and the later
standalone `204` remains independent. This directly explains the recorded
improvement from 34 to 0 for both spurious nested occurrences and signed
boundary errors.

V6 does not change the V5 role classifier. `_v6_mask_rejected_premises()`
passes V6 token dictionaries to `_v5_classify_occurrence()`, then masks the
selected spans. If any mask is applied, `claim_local_critical_value_audit_v6`
passes the modified string to the production V3 validator, which extracts a
new token set. Thus V6 occurrence IDs are diagnostic output, not a contract
between extraction, role, and validation.

## Remaining metrics

The four `global_collapse_errors` and four `type_mismatch_role_errors` overlap:
they are the signed/unsigned cases S03, S14, P02, and P06. V6 retains sign in
the span/raw literal but leaves the underlying polarity comparison keyed by
the V5 normalized token value and inherited role patterns. The role layer
therefore does not deterministically identify the later unsigned occurrence
as rejected in those forms. This is a `ROLE_TO_VALUE_REJOIN` /
`TYPE_REINTERPRETATION` failure, first visible at **ROLE CLASSIFICATION**;
it is not a new nested-boundary failure.

The other eight of the 12 role misses are conservative V5-role misses on
frozen DEV annotations for decimal, duration, version, and date cases:
D01, D03, D06, U05, V03, V07, V09, and T03. V6 preserves their exact spans
but does not recognize the expected rejected-premise role. They are
`ANNOTATION_NOT_EXTRACTOR_OWNED` only for the separate V04/V10 extraction
span mismatches; for these eight, the direct mechanism is
`ROLE_CLASSIFICATION`/`CLAIM_ASSOCIATION_LOSS` rather than boundary loss.

## Version annotation issue

The frozen version slice contains three expected spans not emitted by the
extractor: `version 3`, `9.x`, and the prefixed `9.1.2` annotation. The
extractor emitted `3`, `9`, and the span including its accepted `version`
prefix according to its current contract. Because the population asserted
spans that were not extractor-owned, this is a **MIXED** finding dominated by
`TEST_ANNOTATION_DEFECT`, with a secondary need to make the extractor-owned
span contract explicit. The historical population is preserved unchanged.

Future scored occurrences must use extractor-owned spans unless the test is
explicitly an extraction-contract test.
